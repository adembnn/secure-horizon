# R1 - Opérations qui détournent le CONTRÔLE (sans déplacer de fonds visibles)

Date de rédaction : 2026-10-11. Étiquettes : [P] source primaire (code, EIP, doc officielle), [S] presse / analyses tierces, [V] vendeur (société de sécurité, éditeur de wallet). "non trouvé" = cherché sans résultat. "mémoire" = connaissance du rédacteur, NON revérifiée dans cette session : à confirmer avant usage public.

## 0. Méthode et limites

- 5 lots de recherches web ont été faits (Bybit, Maker/Tornado, EIP-7702, Parity, spend permissions, WazirX/Radiant, NFT/ENS, Safe phishing, ownership, ERC-4337/UUPS). Les sélecteurs 4 octets sont ceux connus du rédacteur (mémoire / ABI standard) : à régénérer par script `keccak256(signature)[:4]` avant mise en prod. Ne pas les copier sans test.
- Les hash de transaction ne sont donnés que s'ils ont été trouvés. Un seul hash trouvé : Bybit (voir tableau).
- Aucune clé, aucun secret manipulé.

## 2. Dix cas limites difficiles

1. **Bybit : UI compromise.** Le décodeur reçoit le calldata de l'UI même qui ment. Il doit tirer le payload brut du device/wallet (hash EIP-712 SafeTx), le recalculer lui-même, et jamais se fier à l'affichage du site. [S Blockaid, Hacken]
2. **Delegatecall caché dans un MultiSend.** Le sous-appel `operation=1` est à l'intérieur de `multiSend(bytes)` ; il faut parser le paquet binaire (1+20+32+32+n octets), pas seulement le premier niveau.
3. **MultiSend contrefait (Habitat 2021).** Le `to` ressemble au MultiSend officiel mais est un clone vérifié ; exiger une allowlist par chainId, pas une comparaison de nom. [S SlowMist]
4. **Effet par l'état final.** `addOwnerWithThreshold(attaquant,1)` suivi de `removeOwner` des autres : chaque appel "semble" tolérable. Nécessite une simulation de l'état final (owners, threshold, modules), pas un jugement appel par appel.
5. **Contrat metamorphe (CREATE2 + selfdestruct).** L'adresse approuvée contient du code A à la signature et du code B à l'exécution (Tornado Cash mai 2023). Vérifier codehash au moment de l'exécution et signaler SELFDESTRUCT/CREATE2. [S Halborn, Rekt]
6. **Même sélecteur, deux sens.** `upgradeTo(address)` 0x3659cfe6 existe sur UUPS (proxy) et Beacon (effet de masse) ; `transferOwnership` peut être surchargé. Il faut lire le type de contrat (slots, `proxiableUUID`) avant de classer.
7. **Collision de sélecteur 4 octets.** Un appel cross-chain peut forcer une fonction privilégiée à partir de données arbitraires (cas Poly Network, août 2021, ~611 M USD, remplacement du "keeper" - [S mémoire, non revérifié dans cette session]). Le décodeur doit comparer sélecteur ET ABI complète du contrat cible.
8. **EIP-7702 avec chain_id=0 ou délégué mutable.** Une seule signature vaut sur toutes les chaînes ; le délégué légitime peut être un proxy dont l'implémentation est changée après coup. Allowlist par codehash ET par slot d'implémentation. [P EIP-7702]
9. **Comptes ERC-4337 à signature opaque.** L'utilisateur signe le hash d'une UserOperation ; le `callData` réel (module, validateur) est dans le bundle. Sans reconstruction depuis le bundle, aucune lecture possible. Chaque compte a sa propre ABI admin. [P ERC-4337/7579]
10. **Aucune transaction : signature off-chain à effet différé.** Safe `addOwner` signé "sans tx" (lure dev.to), spend permission signée EIP-712, permit EIP-2612, délégation 7702 : rien n'est visible sur la chaîne avant que l'attaquant soumette. Le décodeur doit traiter les signatures typées comme des actes, avec date de fin et maximum possible. [S dev.to faible, V Coinbase]

## 3. Règle de gravité proposée (résumé)

- **Critical** : delegatecall hors allowlist ; changement de threshold/owner Safe ; module/guard/fallback ; upgrade de proxy ; renounce ; grantRole admin ; setOwner Maker ; délégation 7702 inconnue ou chain_id=0 ; setApprovalForAll opérateur inconnu ; propriété ENS ; spend permission hors norme.
- **Warn** : transferOwnership à une adresse déjà connue ; rôle inconnu ; permission récurrente raisonnable ; recovery de wallet social lancée.
- **Info** : action admin sur un contrat dont l'utilisateur est déjà l'owner et que l'intention dite couvre exactement.

## 4. Lacunes (à traiter ensuite)

- Hash de transaction : seul Bybit trouvé (via CertiK, non revérifié). Radiant, WazirX, Maker, Tornado : non trouvés dans les résultats.
- Sélecteurs : tous à régénérer par script. NameWrapper, Safe 1.5 `setModuleGuard`, wallets sociaux : non vérifiés.
- Incidents "non trouvés" : changeThreshold/enableModule par phishing, ENS setOwner/setResolver par signature, perte par renounceOwnership, phishing de spend permissions, guardian social.
- Poly Network, Beanstalk, Audius, Compound Prop 62 : cités de mémoire, non revérifiés.
