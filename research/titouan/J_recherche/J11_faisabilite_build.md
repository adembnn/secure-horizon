## 1. Résumé (8 lignes)
1. Faisable en une journée si on garde Hardhat 3 + OpenZeppelin 5.6.1 + invariants Solidity (ou fast-check en secours) et si on écrit soi-même le seau à jetons.
2. Le seau Chainlink CCIP est sous BUSL-1.1 : ne pas le copier. LayerZero (MIT) et ERC-7265 v1-core (CC0) sont réutilisables. [P]
3. TimelockController n'a aucun seuil 2 sur 3 : le 2 sur 3 doit être codé dans le registre (signatures EIP-712 des gardiens) ou fourni par un Safe proposeur. [P]
4. Safe 1.5.0 (ModuleGuard) existe mais n'est PAS listé pour la chaîne 43113 (Fuji) dans safe-deployments ; la 1.4.1 l'est. Ne pas bâtir dessus. [V]
5. Windows : Foundry a un zip win32 natif (v1.8.5), Medusa un binaire win-x64 (v1.5.1), Echidna un zip windows (2.3.3) mais son README ne cite que Linux et macOS. WSL n'a pas de distribution Linux utile ici (seulement docker-desktop, arrêtée). [V]
6. Hardhat 3.19.0 (Node 22.13 minimum, Node 24 présent) sait écrire des tests Solidity fuzz et invariants : un seul outil évite Echidna/Medusa. [V][P]
7. Vérification Fuji : Routescan, clé API quelconque, URL d'API déduite d'un exemple Sepolia (non confirmée pour Fuji) : à tester dès l'heure 1. [S]
8. Gaz : ecrecover 3000 (valeur geth, non confirmée côté Avalanche) ; P-256 6900 (ACP-204, adresse 0x...0100), activation sur Fuji non confirmée par la page ACP. [P][S]

## 4. Exemples minimaux

### 4.1 Demande signée EIP-712 sans revert
```solidity
bytes32 constant REQ_TYPEHASH = keccak256(
  "WithdrawRequest(address client,address to,uint256 amount,uint256 nonce,uint64 deadline)");
function _check(WithdrawRequest calldata r, bytes calldata sig) internal view returns (bool) {
  bytes32 digest = _hashTypedDataV4(keccak256(abi.encode(
    REQ_TYPEHASH, r.client, r.to, r.amount, r.nonce, r.deadline)));
  (address s, ECDSA.RecoverError e, ) = ECDSA.tryRecover(digest, sig);
  return e == ECDSA.RecoverError.NoError && s == registry.keyOf(r.client);
}
```
Les signatures de fonction utilisées sont celles de la doc OZ 5.x citée plus haut. Le fragment lui-même est de moi et n'est pas compilé.

### 4.2 Seau à jetons par bloc (à écrire, pas à copier de Chainlink)
Champs : `uint128 capacity; uint128 ratePerBlock; uint128 tokens; uint64 lastBlock`. Avant tout usage : `tokens = min(capacity, tokens + (block.number - lastBlock) * ratePerBlock)`. `tighten` exige `new.capacity <= old.capacity` et `new.rate <= old.rate`, puis plafonne `tokens` à la nouvelle capacité. Piège : oublier de plafonner `tokens` après resserrage laisse un stock plus grand que la capacité.

### 4.3 Invariant forge/Hardhat 3 (I1)
`invariant_globalBound`: pour tout bloc, `totalOut <= B0 + r0 * (block.number - startBlock)`, avec un handler qui borne les appels (`vm.assume` ou `bound`). Piège : avec `fail_on_revert = false` des appels qui échouent passent sous silence, d'où l'intérêt du handler avec compteurs fantômes.

## 5. Pièges transversaux
- 2 sur 3 des gardiens : TimelockController ne le fait pas. Soit un Safe 2 sur 3 propose au timelock, soit le registre vérifie deux signatures EIP-712 de gardiens distincts (dédoublonnage de l'adresse, nonce par proposition).
- Refus sans revert : un refus qui consomme le nonce doit être écrit avant le return, sinon le rejeu reste possible ; un refus qui ne consomme rien permet le spam d'événements. À trancher.
- Rôles : MONITOR ne doit pas porter DEFAULT_ADMIN_ROLE ; les gardiens ne doivent avoir ni APPROVER ni MONITOR (invariant I4).
- Licences : Chainlink BUSL-1.1 et Echidna/Medusa AGPLv3 (outils, pas du code embarqué). OpenZeppelin, LayerZero MIT ; ERC-7265 v1-core CC0.
- Vérifier sur Routescan avec les mêmes réglages d'optimiseur et le même profil que le déploiement.
- Sous Windows, les chemins avec espaces ("Hack Secure Horizon") peuvent gêner certains outils (remappings Foundry, crytic-compile). Non testé : non trouvé comme problème documenté.

## 6. Risques de build (classés)
1. Seau à rédiger soi-même (BUSL) et à prouver avec I1/I2 : 1 à 2 h, risque d'erreur d'arrondi et de resserrage.
2. Outil d'invariants : si Hardhat 3 ne couvre pas les invariants avec état voulus, repli sur forge (zip win32) ; Echidna/Medusa en dernier recours (Python, Slither, solc à installer).
3. Vérification Routescan Fuji : URL d'API non confirmée, plan B vérification manuelle via l'interface.
4. Disponibilité P-256 sur Fuji non confirmée : ne pas en faire une dépendance, ecrecover suffit pour la V1.
5. Safe 1.5.0 absent sur Fuji : pas de ModuleGuard déployé par Safe ; déployer soi-même coûte du temps et sort de la V1.
6. Gaz Fuji limité : prévoir un portefeuille dédié ; mesurer le gaz de `tryWithdraw` avec `eth_estimateGas`.
7. Version fast-check : API à valider ; garder Foundry/Hardhat 3 comme première option.
8. Hardhat 2 contre 3 : choisir Hardhat 3 (ESM, Ignition 3.1.8, hardhat-verify 3.1.2) pour éviter de mélanger les séries. Incompatibilités de plugins entre séries : risque réel, non quantifié.
9. Incertitudes de la lecture : plusieurs fiches sont des résumés automatiques de pages web ([S]). Vérifier les commandes avant de s'y fier.
10. Aucune clé ni secret n'a été utilisé ou saisi dans cette recherche.
